# EGTBにおける駒数 $k$ の定義と3階テンソル空間 $\mathcal{V}$ への完全写像

ATShogi-OM Extremeにおける終盤データベース（EGTB: End Game Table Base）および最適な最大駒数 $k$ の決定モデルは、将棋特有のルールである「持ち駒」を幾何学的に内包し、トポロジカルに定式化されています。

## 1. 駒数 $k$ の数理的な内訳（持ち駒の完全内包）
ATShogiにおける $k$（例えば EGTBL 4.0 における $k=4$ や、実機キャッシュ常駐設計における $k=7$）は、単なる盤上の駒数ではなく、**「王（玉）2枚 ＋ それ以外の駒（自由駒 / 攻め駒・守り駒） $k-2$ 枚」** として厳密に定義されています。

将棋の性質上、盤上から消えた（取られた）駒は「持ち駒」となって再利用されます。したがって、この $k-2$ 枚の自由駒（Free Pieces）は、**「盤上にある状態」だけでなく、先手または後手の「持ち駒として保持されている状態」も含めて計算されます。**

これらはすべて、玉（King）に対するトポロジカルな相対配置空間（ファイバー $F$）として一元的にモデル化・包含されています。

## 2. 3階テンソル空間 $\mathcal{V}$ への完全写像
持ち駒を含むあらゆる局面情報は、以下の3つの情報を基底とする **$81 \times 81 \times 81$ 次元（計531,441次元）の3階テンソル空間 $\mathcal{V}$** に射影（エンコード）されます。

1. **先手の持ち駒状態（81次元）**
2. **盤面の駒配置（81次元）**
3. **後手の持ち駒状態（81次元）**

### トポロジカル計算と線形時間の保証
MERA/PEPSによる動的局所縮約や、TNRG SVD（テンソルネットワーク繰り込み群）によるコアテンソルへの圧縮計算は、盤面だけでなくこの「持ち駒を内包した3階テンソル」全体を対象にシームレスに実行されます。

これにより、持ち駒の複雑な組み合わせ変化や打つ手・取る手による状態遷移が発生しても、多様体上の連続的な変形として扱われます。結果として、**計算量 $O(k)$ の線形時間による代数参照アルゴリズム**は、100%の整合性を保ったまま完全に動作し、極限の速度（0ms）での詰み経路（測地線流）の探索・評価を可能にします。
